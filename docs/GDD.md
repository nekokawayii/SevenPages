# 《七页轮回》设计文档 v0.1

> 对抗式卡牌游戏 · 2 人 · 单人可对 AI 陪练
> 本文档是模板阶段的唯一规则来源（Single Source of Truth）。代码按本文实现。

---

## 一、世界观内核

每个人手上都有一本《轮回之书》，全书只有七页。

你的命，就是这七页。每受一次伤，墨迹渗开一页；七页撕尽，你便在轮回中重活一次——
但记忆会留下，业障也会留下。第三次轮回，你就再也回不来了。

**核心意象：书页即生命，轮回即败北倒计时。**

---

## 二、胜负条件

任意一方满足以下任一条件即败北：

1. **三度轮回** —— 累计触发 3 次「轮回」（Page 全部撕尽）。
2. **书尽** —— 牌库与手牌皆空，仍需要抽牌时（疲劳）。
3. （预留）**封印** —— 被对方用「封印」类卡牌钉死全部页数。

---

## 三、生命 / 页系统（本作核心机制）

| 概念 | 数值 | 说明 |
|---|---|---|
| 每页墨量 `inkPerPage` | 3 | 每页的耐久 |
| 总页数 `pageCount` | 7 | 固定 |
| 每条命的墨量 = 7 × 3 = 21 | — | 等价血量，但表现分页 |
| 单页撕尽 | 墨 ≤ 0 | 撕页 → 翻到下一页，墨重置为 3 |
| 全书撕尽 | 第 7 页撕尽 | 触发一次「轮回」 |

> 数值经过 500 局无头模拟校准：每页墨量 4→3、基础灵 2→3、每回合抽牌 1→2，
> 对局长度从 46 回合压到 24 回合左右。

### 轮回结算
- 页指针回到第 1 页，墨重置为 3；
- 「轮回次数 +1」；
- **业障**：向该玩家牌库洗入 1 张 `Karma`（业障）诅咒牌；
- **宿慧**：该玩家获得 1 层「宿慧」，每层使每回合「灵」+1（永久，最多 3 层）；
- 若轮回次数达到 3 → 立即败北。

> 设计意图：受伤不只是掉血，而是在加速「轮回倒计时」。玩家会主动权衡——
> 是该硬吃伤害保存牌，还是早早轮回换取宿慧（伤害更高）但逼近三次上限。

## 四、回合流程

```
回合开始 → 灵重置 → 抽牌(1) → 行动阶段(可多次出牌) → 回合结束 → 交给对手
```

| 阶段 | 规则 |
|---|---|
| 灵上限 `maxSpirit` | 3 + 宿慧层数，上限 10 |
| 初始手牌 | 首回合可见 4 张（先手） / 5 张（后手补偿） |
| 每回合抽牌 | 2 张 |
| 手牌上限 | 10 张（超出则燃烧多余） |
| 出牌 | 消耗「灵」，可连续出到灵不足 |
| 行动次数 | 模板阶段不限制次数，只受「灵」约束 |
| 疲劳 | 牌库空时抽牌 → 每张造成 1 点墨伤（递增 1/2/3…） |

### 卡牌类型（模板阶段）
- **术** `Spell` —— 即时生效（伤害/治疗/抽牌/增益）
- **咒** `Curse` —— 负面牌，抽到即生效或占用费用（业障即此类）
- **式** `Rite` —— 结附于自身/对方的状态（如「逆墨痕」：每回合失 1 墨）
- （预留）**域** `Domain` —— 持续场地效果

> 模板阶段**不做随从/召唤物**，纯法术对抗，保证规则可验证、AI 可写。

## 五、卡牌数据模型

```jsonc
{
  "id": "strike_ink",          // 唯一 ID
  "name": "墨刺",
  "type": "Spell",             // Spell | Curse | Rite
  "cost": 1,                   // 灵
  "target": "Enemy",           // Self | Enemy | None
  "text": "对敌方造成 2 点墨伤。",
  "art": "placeholder_01",     // 占位图 key，后续替换为千问生成图
  "effects": [                 // 效果为数据，由效果解释器统一执行
    { "kind": "Damage", "amount": 2 }
  ],
  "tags": ["attack", "basic"]
}
```

设计原则：**效果是数据，不是代码分支**。新增一张牌 = 写一个 JSON，
核心引擎（`EffectResolver`）只认 `kind`，卡池与规则解耦。

## 六、占位符约定

模板阶段所有卡面使用统一占位符：

- 图片：`Assets/Art/Placeholder/card_placeholder.png`（千问生成后替换）
- 卡牌 ID 与名称用真实设计（`墨刺`/`业障`），便于后续直接换美术；
- 每张牌在 `art` 字段写 `placeholder_XX`，美术到位后批量替换。

## 七、技术架构

```
[Unity 客户端]  ←→  [纯 C# 规则引擎 Core]  ←→  （后续）服务器
       ↘_____________ 同一份 Core _____________↙
```

- **SevenPages.Core** —— 纯 C# 类库（无 UnityEngine 依赖），规则/状态机/结算。
  可被 Unity、服务器、单元测试、AI 同时引用。**这是本项目的命脉。**
- **SevenPages.Unity** —— Unity 工程，只负责表现层（渲染、动画、输入）。
- **AI** —— 基于 Core 的贪心/评估式 AI，先做能打的那种。
- 服务器联机：Core 将来原样跑在服务端，客户端只发「意图」（Intent）。

> 为什么把规则抽成纯 C#：Unity 里调试规则极慢，且未来联机必须服务端权威。
> 现在多花一天，后面省一个月。
